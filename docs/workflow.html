Phase 0: System Setup

Frequency: One-time configuration

  • ✓ Install modules in correct order (Levels 1-5)
  • ✓ Configure document types (Passport, License, etc.)
  • ✓ Create project templates for UAE services
  • ✓ Set up task libraries with checkpoints
  • ✓ Configure compliance rules and risk matrix

Phase 1: Product Configuration

Module: project_templates_basic + unified_documents

Service Product Setup

Product: "FZCO Formation - Standard Package"
├─> Type: Service
├─> Service Tracking: "new_workflow" (template-based)
├─> Project Template: "FZCO Formation Template"
├─> Required Documents:
│   ├─> Passport Copy
│   ├─> Emirates ID
│   ├─> Proof of Address
│   └─> Business Plan
├─> Deliverable Documents:
│   ├─> Trade License
│   ├─> MOA (Memorandum)
│   ├─> Share Certificates
│   └─> Certificate of Incorporation
└─> Partner Required Fields:
    ├─> Nationality
    ├─> License Authority
    └─> Business Activity

Phase 2: Sales Process

Step 1: Create Quotation

  • Navigate to Sales → Quotations → Create
  • Select customer
  • Add service product(s)
  • Set pricing and payment terms

Step 2: Customer Data Collection

⚠️ GATE: Required partner fields must be filled before SO confirmation

If missing fields detected:

  • System opens wizard to collect data
  • Captures nationality, license authority, activities
  • Validates completeness before proceeding

Step 3: Confirm Sale Order

  • Invoice Creation: Based on invoicing policy
    • Prepayment: Invoice created immediately
    • Milestone: Multiple invoices per phase
    • Post-paid: Invoice on delivery
  • Project Auto-Creation:
    • Creates project from template
    • Generates tasks with checkpoints
    • Creates document placeholders
    • Sets up folder structure
    • Project state: b_new

Phase 3: Document Collection

Module: unified_documents

Required Documents Workflow

1. Auto-created (state: draft)
   └─> System creates placeholders based on product config

2. Client Upload (state: uploaded)
   └─> Client uploads via portal or email

3. Verification (state: complete)
   └─> Document controller clicks "Complete Required"
   └─> Reviews validity, expiry dates

4. Confirmation (state: confirmed)
   └─> Project manager clicks "Confirm Required"
   └─> Document locked, checkpoint updated

Alternative: Return Flow
   └─> Click "Return Required"
   └─> Add notes explaining issues
   └─> Client re-uploads
   └─> Repeat verification
⚠️ GATE: All required documents must be confirmed before project can move to c_in_progress

Phase 4: Handover Data Collection

Module: project_handover_notes

Company Formation Details

  • Basic Info: Company names (3 options), legal entity, authority
  • License: Validity period, business activities
  • Operations: Countries, visa requirements, office space
  • Shareholding: Number of shares, price, distribution
  • Tax: TRN, registration status, filing schedule

Workflow States

Draft → Complete → Confirm → Approved
          ↓
       Return → Update → Complete
⚠️ GATE: is_confirm_hand = True required before deliverable document confirmation

Phase 5: Compliance Processing

Module: project_compliance

Risk Assessment

Risk Category Weight Factors
Service Risk 15% Complexity, offshore structures
Product Risk 15% Banking, crypto, financial services
Client Risk 15% First-time vs repeat customer
Geography Risk 20% High-risk jurisdictions
PEP Risk 15% Politically exposed persons
Sanction Risk 10% Sanctioned entities/individuals
Adverse Media 10% Negative news, legal issues

UBO Identification

System automatically calculates Ultimate Beneficial Owners (>25% ownership):

Example:
Company: Tech Innovations FZCO
├─> Individual A (40%) → UBO ✓
├─> Company B (35%)
│   ├─> Individual C (60% of B) → Indirect 21%
│   └─> Individual D (40% of B) → Indirect 14%
└─> Individual E (25%) → UBO ✓

Result: 2 UBOs identified
⚠️ GATE: is_confirm_compliance = True required before project completion

Phase 6: Service Execution

Module: project_checkpoints_basic

Task Progress with Checkpoints

Task: "Submit License Application"
Checkpoints:
☐ Application form completed
☐ Passport copies attached
☐ Business plan reviewed
☐ Government fees calculated
☐ Client approval received
☐ Application submitted to authority
☑ Submission receipt obtained
☑ Application tracking number recorded

Progress: 25% → Updates automatically

Milestones

  • Contract Signed (Day 0)
  • Documents Collected (Day 3-5)
  • Name Approved (Day 7-10)
  • License Submitted (Day 12-15)
  • License Issued (Day 20-25) ← Triggers deliverable creation
  • Documents Delivered (Day 28-30)

Phase 7: Deliverable Preparation

Module: unified_documents

Deliverable Documents Workflow

1. Auto-created at "License Issued" milestone
   └─> state: draft

2. Service team uploads finals
   └─> Trade license PDF
   └─> Certificate scans
   └─> Share certificates
   └─> Click "Complete Deliverable"

3. Quality check
   └─> Document controller verifies
   └─> Click "Confirm Deliverable"
   └─> state: confirmed

4. Ready for handover
   └─> Link to handover package
   └─> Schedule client appointment
⚠️ GATE: All deliverable documents must be confirmed before project completion

Phase 8: Handover & Completion

Final Steps

  1. Prepare Handover Package
    • Collect all confirmed deliverables
    • Create physical folder/cabinet entry
    • Prepare sign-off document
  2. Schedule Client Appointment
    • Coordinate with client
    • Arrange office visit or courier
  3. Physical Handover
    • Client receives documents
    • Sign handover receipt
    • Upload signed receipt
  4. Project Completion
    • Mark project as complete
    • Trigger commission calculation
    • Archive project files
    • Send satisfaction survey

Complete UAE Service Example: FZCO Formation

Timeline: 30 Days

Week 1: Setup & Documentation

  • Day 1: SO confirmed, project created, documents requested
  • Day 2-3: Client uploads passport, Emirates ID, proof of address
  • Day 4: Document verification complete
  • Day 5: Handover data collected, compliance check initiated

Week 2: Name Approval

  • Day 8: 3 company name options submitted to DMCC
  • Day 10: Name approved, reservation certificate issued
  • Day 12: Compliance approved, risk rating: Low

Week 3: License Application

  • Day 15: License application prepared and reviewed
  • Day 16: Client approves application
  • Day 17: Application submitted to DMCC
  • Day 18-20: DMCC processing

Week 4: Issuance & Handover

  • Day 23: Trade license issued by DMCC
  • Day 24: Deliverable documents created
  • Day 25-26: MOA, share certificates prepared
  • Day 27: Quality check, all docs confirmed
  • Day 28: Handover package prepared
  • Day 29: Client appointment, physical handover
  • Day 30: Project completed, commission triggered
